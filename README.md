# AdGuard CLI Debian Package

This repository contains a Debian package for [AdGuard CLI](https://adguard.com/en/adguard-cli/overview.html), configured to run as a system-wide `systemd` service.

The package is intended for Debian-based systems running on `amd64` architecture.

AdGuard CLI supports a trial period before a license key or serial number is required.

For the official AdGuard for Linux product information and installation instructions, see the [AdGuard for Linux overview](https://adguard.com/en/adguard-linux/overview.html?source=ag_products_page). This repository provides an alternative Debian package-based installation and is not the official AdGuard installer.

## Features

- Installs the AdGuard CLI executable under `/usr/lib/adguard-cli/`.
- Provides the `adguard-cli` command at `/usr/bin/adguard-cli`.
- Installs and manages the `adguard-cli.service` systemd unit.
- Runs the service with a dedicated system user and group named `adguard`.
- Stores persistent service data in `/var/lib/adguard-cli`.
- Supports migration from legacy installations under:
  - `/opt/adguard/.local/share/adguard-cli`
  - `/home/*/.local/share/adguard-cli`
- Removes the legacy systemd unit symlink when it points to the previous installation path.

## Requirements

- Debian or a Debian-based distribution.
- `systemd`.
- `amd64` architecture.
- Root or `sudo` access.

The package depends on `adduser` to create the dedicated `adguard` system user and group.

## Installation

Install an existing package with:

```bash
sudo apt install ./adguard-debian_1.0.0_amd64.deb
```

During installation, the package:

1. Creates the `adguard` system user and group if they do not already exist.
2. Creates `/var/lib/adguard-cli` with the appropriate ownership and permissions.
3. Migrates configuration data from supported legacy locations when necessary.
4. Reloads, enables, and starts the systemd service when systemd is available.

The service is started automatically after installation so that the AdGuard trial can be used immediately. On an upgrade, an existing installation is restarted automatically.

## Activation

Activation is performed separately and is not automated by the package. This prevents license keys from being stored in package metadata, shell history generated by the package, or repository files.

Run the activation command as the service user:

```bash
sudo -u adguard env \
  HOME=/var/lib/adguard-cli \
  AG_CLI_DATA_PATH=/var/lib/adguard-cli \
  /usr/bin/adguard-cli activate
```

Follow the interactive prompts and provide the license key or serial number when requested. The activation data is stored in:

```text
/var/lib/adguard-cli/adguard.conf
```

If the CLI requires initial configuration, run:

```bash
sudo -u adguard env \
  HOME=/var/lib/adguard-cli \
  AG_CLI_DATA_PATH=/var/lib/adguard-cli \
  /usr/bin/adguard-cli configure
```

After activation and configuration, restart the service:

```bash
sudo systemctl start adguard-cli.service
```

Check the service status with:

```bash
systemctl status adguard-cli.service
```

If required, enable and start the service manually:

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now adguard-cli.service
```

## Service management

Use the following commands to manage the service:

```bash
sudo systemctl start adguard-cli.service
sudo systemctl stop adguard-cli.service
sudo systemctl restart adguard-cli.service
sudo systemctl enable adguard-cli.service
sudo systemctl disable adguard-cli.service
```

View service logs with:

```bash
sudo journalctl -u adguard-cli.service -f
```

The service runs AdGuard CLI in the foreground so that systemd can monitor and restart it when necessary:

```text
/usr/bin/adguard-cli start --no-fork --log-to-file
```

## Data and configuration

The system service uses the following account and data directory:

```text
User:    adguard
Group:   adguard
Data:    /var/lib/adguard-cli
```

The service explicitly sets:

```text
HOME=/var/lib/adguard-cli
AG_CLI_DATA_PATH=/var/lib/adguard-cli
```

This prevents the service from depending on the home directory of the user who installed the package or on a logged-in interactive user.

## Running the CLI manually

To run commands with the same environment used by the system service:

```bash
sudo -u adguard env \
  HOME=/var/lib/adguard-cli \
  AG_CLI_DATA_PATH=/var/lib/adguard-cli \
  /usr/bin/adguard-cli --help
```

Refer to the AdGuard CLI documentation for the available commands and configuration options.

## Removal

Remove the package while preserving its data:

```bash
sudo apt remove adguard-debian
```

To remove the package and its service data:

```bash
sudo apt purge adguard-debian
sudo rm -rf /var/lib/adguard-cli
```

Make sure the service is stopped before manually removing its data:

```bash
sudo systemctl stop adguard-cli.service
```

## Building the package

This repository contains a prepared Debian package tree that can be built with `dpkg-deb`:

```bash
dpkg-deb --build --root-owner-group . ../adguard-debian_1.0.0_amd64.deb
```

Inspect the generated package with:

```bash
dpkg-deb --info ../adguard-debian_1.0.0_amd64.deb
dpkg-deb --contents ../adguard-debian_1.0.0_amd64.deb
```

Generated Debian packages and other build artifacts are excluded by `.gitignore`.

```text
├── postinst
├── postrm
├── preinst
└── prerm
usr/
├── bin/
│   └── adguard-cli -> /usr/lib/adguard-cli/adguard-cli
└── lib/
    ├── adguard-cli/
    └── systemd/system/
        └── adguard-cli.service
```

## Compatibility and scope

This package is designed for `amd64` Debian-based systems using systemd. Other architectures and init systems are not currently supported by the package metadata and service integration.
